# acheng-assets

决定资产顺序、逐图用途、关键帧依赖与场景修复时，按[局部决策指南](../../references/decisions/assets.md)对应节执行；区分风格、身份、状态、空间、单帧和接触表，再建立原有依赖与编号。

H3 引用衔接另读[114 绑定合同](../../references/114-reference-binding-delivery.md)。assets 提供 asset_plan 实际选用媒体的文件/哈希/版本与状态，核对 shots.reference_requirements；不抢写 model 的 Segment 标签。尚未生成的 .image.txt 只能是制作指令，不是媒体。合理复核可读相邻字段，写入仍由唯一 owner 完成。

本文件是acheng-director随包专业子入口，按路径加载；主导演负责真值、版本、对象创建和最终合并。它不自动启动代理或调用模型。

先读[本分支核心合同](../../references/60-assets-and-keyframes.md)、[专门规则](../../references/61-asset-dependency-production.md)、[STYLE MOTHER 风格锚定合同](../../references/62-style-anchor.md)与[场景设计适配合同](../../references/105-scene-design-adapter-v4.md)；同时遵守[模块回包合同](../../references/91-module-orchestration.md)。只读取本任务依赖，保留上游来源与冻结项。

先从剧本与逐镜用途建立asset_plan，区分基础资产、变化版本和关键帧。STYLE_MOTHER 与 style_lock 是可选的风格一致性建议；用户未要求时不额外创建，也不作为编译前置。**本模块只交付高质量提示词文本与上传指引，严禁智能体直接调用生图工具。** 如需跨资产统一风格，可输出一张低污染、无剧情身份、无文字标志的 `STYLE_MOTHER.image.txt`；没有这张图时继续其他提示词和编译。需要统一跨资产画风时，可将 `STYLE_MOTHER` 加入角色、场景、道具和关键帧提示词的参考槽位，并写明保留/排除范围（继承媒介、线条、阴影、色板、材质响应，排除身份/构图污染），有助于全套资产保持一致画风。所有生成的资产提示词必须包含无文字无水印负向约束（No text, no watermark）；人物四视图必须保持纯粹（正脸特写+正/侧/背面全身，两手中立空手，严禁硬塞武器道具）；关键帧必须视情况组合引用风格母图、场景图、各出场角色图与道具图，并在提示词中以 `@图片1`~`@图片N` 指派分工，配套上传助手。角色身份图采用两阶段：先生成一张单人中立全身身份图，锁定脸、体态、发型与服装；确认一张真实归档输出作为身份源后，再以它作为明确参考生成四视图基准板。每个正式资产目标/阶段使用一个固定智能图片节点；提示词迭代时复用该节点，以追加结果方式保留每次成功历史，不得每次尝试新建配置节点。身份图与四视图是两个不同阶段，可各自拥有一个固定节点，但同一阶段始终复用原节点。单张身份图与四视图各自保留用途和历史，四视图不能替代身份源；若首阶段有多个结果，先明确选定真实输出再进入四视图。两阶段均写入角色名与 `state_label`。身份图先明确人物类型读法（如仙门道者、妖族贵胄、山野精怪或凡人修士），让轮廓、剪裁与材质一眼服务于该类型；至少写出两至三项全身图可见的层叠、衣领/肩线、袖型、下摆、织锦或刺绣细节，并选一个可在后续四视图重复的识别纹样。避免把仙道或妖物写成泛古装、素布长袍或日常村妇，也避免堆饰物来替代服装设计。成年女性妖物若要求妖艳，可用修身剪裁、肩颈/锁骨露肤、开衩与不透内层、薄纱外层、妆发和眼神营造魅惑与危险感，不要默认全身包裹；幼态角色保持年龄适配，以灵异眼神、配色、纹样和衣料动势表现妖气，不做成人化性感造型。妖怪身份纹样只能作为人类服装的织纹或绣纹出现，不得因此改变本体设定或引入未确认的兽类结构。按依赖顺序制作；每个参考独立规定身份/场景/构图等用途。读IM2七步与当前条件规范，最终正文完整展开身份、状态、材料与光路。

用户选用风格参考时，在对应资产卡中按实际编号与绑定说明其媒介、线条、阴影、色板、材质响应和排除范围。没有风格锚点时将一致性建议作为提示；只有真实选作本次生成输入的参考才要求文件、版本、节点和哈希有效。返回asset_plan、asset_cards及经主导演允许的具体外貌描述，不覆盖人物身份或剧情。技术可用但未审核的真实媒体可以作为输入并保持 generated 状态；实际选择的参考缺文件或绑定错误时，才将依赖目标标为草案并列出缺项。

场景概念需求由嵌套的 `scene-design` 适配器按需触发。它先生成独立 `scene_art_direction.json` 和图像提示词，再由 assets 校验场景几何、版本、依赖与参考图；场景支路不直接写生产真值，不能把 moodboard 图片自动当作 STYLE_MOTHER。

字段写入白名单取[模块登记](../../data/module-registry.json)。回包包含request_id/input_revision/module/status/attempt/patch/evidence/unresolved；最多初次加一次有证据的修正。只改允许路径，不能把其他模块的建议直接写成已确认事实。


### 固定角色四格模板（用户指定）
先出单张中立全身身份图；以该图作为确定的身份参考后，才制作角色四格板。第二阶段统一为2×2：左上锁骨以上正脸，右上锁骨以上右侧脸，左下锁骨以下无头正面服装全身（头脸完全裁掉、双腿鞋完整），右下后脑到鞋底完整背面。正交无透视畸变、中性浅灰背景、空手中立、无文字。四格板必须引用已归档的身份图，只继承它实际提供的身份、发型、体态与服装特征；排除身份图的姿势、构图、背景和光位。附属结构与画风只读项目角色事实，不复制示例角色的狐耳九尾。单张身份图保持为独立身份源与历史媒体，不被四格板覆盖；已确认媒体保持原版本，非当前格式源稿按主 Skill 的升级提示处理且不在原稿上迁移。
