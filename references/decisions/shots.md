# 摄影：从必须看清的事件选择镜头

## Segment 边界：切镜、尾帧与 Motion Context

每条 `from → to` 边界默认允许剪辑，`motionContext=false`、`tailFrame=false`。人物、服装、道具或场景一致不构成开启理由；对白正反打、听者反应、换景别、换机位与正常硬切优先保持独立生成。允许所有边界均关闭，不为比例、模板检查或“更连贯”开启潜空间续写。

只有导演明确要求此处不能切镜，且两段是同一连续摄影镜头因生成时长限制拆开的部分，才开启 Motion Context。reason 必须写清不能切镜的叙事依据、连续的机位与运动，以及下一段必须延续的具体动作/声音相位。仅有对白、声音不断、运动方向一致或同一动作未完不够：这些内容可以通过剪辑、声音桥与状态描述承接。不能确定需要同一不间断镜头时保持关闭。

尾帧参考另行评估，但与 Motion Context 互斥：只允许都关闭、仅尾帧或仅 Motion Context，禁止两项同时开启。下一段确实需要前段末帧约束姿态、接触、持物或动作相位时可以开启尾帧，下一段仍可重新构图和切镜。尾帧不保证同机位连续运动，不自动开启 Motion Context。时间跳跃、动作重置或地点变化需要重新建立状态时关闭尾帧。

两项都作用于 `to` 段的生成输入，而不是 `from` 段自身：A→B 开启尾帧表示 B 参考 A 的末帧；开启 Motion Context 表示 B 消费 A 的 AV latent/上下文。画布开关保存在 A 段，代表 A→B 的出边；不得误写在 B 段而使其传给 C。末段无出边，两项关闭。只登记真实需求，不自动迁移历史边界或重新生成历史媒体。

## 对白摄影与剪辑

对白摄影的自动编译插入目前暂时停用。H3 编译器不再按说话人或台词帧窗追加近景、反打或听者反应切镜；保留源稿中的摄影设计和逐字对白。需要切镜时由作者明确写入 Shot 摄影设计。

恢复自动编译插入时，每条新增视角都必须写明本镜局部时刻、观看者、切镜理由、轴线/视线和静默/口型边界；插入提示不得截断原本动作或接触。当前阶段不执行这些插入。

摄影师需要固定镜头覆盖时，才声明 `storyboard_policy: {version: 1}`，并在对应镜头填写 framing、attention_subject_ids、editorial_reason；程序此时校验结构字段及帧窗。当前普通新旧源稿均不由编译器自动补充对白视角提示。

每个 Shot 的 camera 必须填写：`framing` 为 EWS/WS/FS/MS/MCU/CU/ECU（大远景/远景/全景/中景/中近景/近景/大特写）；`attention_subject_ids` 为已登记人物或对象的非空 ID 数组；`editorial_reason` 用完整英文说明为何切入或保持、承载哪项信息或反应。中文用途保存在 display_summary，内部 ID 不进入模型正文。

中景或全景用于空间建立、走位、接触和道具关系；该事件结束后重新判断观看重点，不默认保持多人构图。连续长镜可成立，但必须说明持续发展的表演、调度或信息变化。没有固定切镜秒数、近景比例或镜头数量配额。

摄影视角切换必须建立独立 Shot 和整数帧窗，不能在一个 Shot 中写“必要时切近景”。先定 Shot 后装箱；单镜可以短于 4 秒，生成窗口限制只约束 Segment。保持轴线、视线、演员起止状态和道具归属一致。

拆镜时以全局声音时间重分配每镜局部对白、表演时间、参考覆盖和连续性记录；不得复制整句到两个镜头造成重复，也不得把听者画外声误标成叙事旁白。跨镜一句话按实际词句边界分配，保留原文顺序及发声者，口型仅由可见发声者承担。

结构缺项阻止编译；多人中景对白、多人共用一镜或正文景别矛盾仅提示复核。程序不能据提示自行插镜。Subject Prompt Assembly 组件不声明策略时按本合同的默认行为处理；不为旧版 Director 源稿提供兼容分支。

执行方式见 [115](../115-directed-decisions.md)。以确认节拍、场景地图、人物位置和已有 ShotSpec 为输入。写回本模块原 camera/visual/characters/时序/reference_requirements；不改对白、胜负或资产批准状态。

## C1｜先判断是否需要运动

1. 本镜必须看清哪个瞬间：物件离手、接住、眼神回应、碰撞接触，还是某物被揭示？只选本镜实际承担的事件，并指出承载它的部位。
2. 当前机位能否在所需时段看见该部位？能看见且无跟随／揭示需求时，固定机位就是完整候选。看不见时先确定是裁切、人物遮挡还是距离问题。
3. 人物出画才考虑跟随；新信息在画外才考虑摇移或揭示；距离变化确有用途才考虑推进或拉远。先写运动目的，再按 [20](../20-storyboard-compiler.md) 与 [21](../21-genre-camera-capacity.md) 查对应家族，核对真实目录 ID。
4. 仅当两个方案都能完成该事件且取舍影响可读性时，比较各自会遮住什么、提前暴露什么。记录采用项及一条具体理由即可；不固定每镜辩论两个编号。

例：两人原地交钥匙，中景已看清两只手，保持固定可成立；推进若裁掉接收手，就不适合这个交接节拍。

看不清原因仍未定位时，按缺口选[观察点 Q08](../inquiries/shots.md#q08)、[焦点/纵深 Q10](../inquiries/shots.md#q10)或[前景遮挡 Q11](../inquiries/shots.md#q11)。光学观感候选见[视觉库](../116-visual-reference-library.md)；先确定要同时看清的对象，再查条目，不凭镜头品牌改变机位、画幅或已批准媒介。

## C2｜切镜后方向似乎反了

读取上一镜世界位置、人物面对方向、相机所在侧和当前机位。先判断人物是否真实换位；没有换位时检查相机是否跨过关系轴。跨轴可由已批准的连续移动、轴上镜头或重新建立方位解释，不能机械禁用。世界左右与屏幕左右分开记录；屏幕坐标是构图设计，不伪称实测。只补能消除当前歧义的空间信息。

具体检查切点目标时使用[视线接力 Q09](../inquiries/shots.md#q09)：指出前镜正在看的部位与后镜承接的对象，而非泛问“构图高级吗”。

## C3｜参考图承担什么作用

从本镜必须保持的身份、场景结构、道具形态、单一动作相位中挑实际需要图片支持的项。在 reference_requirements 写已有 asset_id/entity_id、版本与用途。人物四视图只供身份；单帧锚点才约束具体时刻的构图；整张接触表只供分镜规划，不能当单个首帧。需要裁图时由 assets 建立可追溯派生资产，model 分配局部标签。

## C4｜时长装不下

先保留已锁对白、决定性事件和必要反应，再检查可同时发生的背景动作。仍超容量时定位可合法切开的动作节点交主导演；不通过加速全部台词、删受击结果或把完整段写成摘要取得时间闭合。镜头事件顺序稳定后再运行整数帧检查。

事件齐全却读不清时，用[认出变化所需时段 Q33](../inquiries/shots.md#q33)寻找具体被切走的信息；不固定插入空镜或停顿。

## C5｜群戏有三人以上，观看对象不明确

只在群戏或发言对象改变时读取[关注关系 Q12](../inquiries/shots.md#q12)与[视线对象 Q13](../inquiries/shots.md#q13)。先列本拍发起者、接收者、真正影响下一步的旁观者；再决定谁需清楚、谁可留在背景。对象更换需要可见依据，不硬凑三角、不让所有人同时抢焦点。输出仍是原 characters/camera/visual。

## C6｜多主体近景中的精确道具关系

当近景中多个主体同时可见并受关注，且本镜还要读清道具对身体部位的精确指向或接触时，先判断这些信息能否在同一最终构图里成立。`attention_subject_ids` 登记观看重点，不规定主体等大、同平面或同等清晰。

在 `visual` 与 `camera` 的摄影描述中具体说明：

1. 本镜唯一的主要视觉信息，以及承担它的主视觉主体；其他主体完整入画、局部入画、虚焦或画外的方式。
2. 角色和目标的相对屏幕位置，道具从哪侧进入画面及运动路径。
3. 精确目标部位，以及道具最终停在目标前、与目标接触或离开目标的状态；需保留间隙时写清可见间距关系。
4. 镜头运动过程中关注点如何转移，以及运动结束/急停后观众必须读到的构图；说明道具、手臂和面部之间会不会互相遮挡。

如果双人完整表演与精确道具关系无法在当前景别同时读清，给出加宽景别或在合法叙事节点另切 Shot 的方案与信息取舍，由作者决定。不得把“MCU + 多人”本身判为错误；不得自动拆镜、改景别、替作者指定主次或发明接触结果。编译复核只提示上述信息是否需要作者确认，不自动改写源稿。
